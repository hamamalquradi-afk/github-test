# Compact offline theme gallery

The Appearance → Themes screen adds **80 curated built-in appearances in 10 categories** (8 each): dark, light, black/gold, neon palettes, gradients, minimal, nature, flowers, geometric, and coding. IDs, names, Arabic names, palettes and supported artwork are in `assets/compact_themes.json`; `generate_catalog.py` is its maintainable source. All artwork is original deterministic Android Canvas drawing licensed GPL-3.0-only with this overlay. No network, image licenses, animations, glass/3D claims, new runtime dependencies or external preview assets are involved.

The adaptive Compose grid is lazy. Cards open an isolated preview; their Apply buttons also support one-tap application. A preview uses the real keyboard parser, layout geometry, key drawables, fonts, hints and `KeyboardView`, with explicitly supplied renderer colors. It never changes live appearance preferences. Preview choices include the current subtype (including imported layouts), Arabic and English. A bounded 8 MiB thumbnail cache avoids rendering off-screen cards and storing full-size preview bitmaps. The same immutable theme definitions and Colors factory serve the live IME and previews.

Gallery selection is one separate preference. Existing palettes, custom background files, layouts, geometry, fonts, shortcuts, language choices and voice settings are not rewritten by applying presets. “Use my Appearance settings” returns to the native customization settings. Editing native color/style/border preferences also hands control back to the native engine. Restore default resets only native theme colors/style/borders/day-night appearance, hides rather than deletes old image files, and retains saved custom appearances. If a native appearance is active, it saves a snapshot of the currently visible palette before resetting it.

Customize a copy supports background/key/function-key/label/accent colors, all three native styles, borders and separate portrait/landscape device images. The original preset remains immutable. Saves have independent IDs and appear under My appearances. Imported images are copied to private device-protected storage, EXIF orientation is corrected where supported by Android's ExifInterface, dimensions are bounded to 1280 pixels / about 1.1 megapixels, and bytes are recompressed to WebP. A 6 MiB decoded-image LRU bounds retained image memory. Invalid/oversized inputs leave existing images intact; missing/corrupt/private-path-invalid images fall back to original vector artwork. Photos use opaque keys and a background overlay. Label and action-icon contrast is selected by WCAG contrast calculation. These are static image/gradient effects.

The existing pinned upstream and overlay workflow remain in place. The new exact-match patch module is `apply_themes.py`; it fails on source drift. `VoiceInputController.java`, its regression tests and all layout files remain unchanged. The existing Compact debug variant keeps its application ID/providers; its experimental versionCode increases to 4301. An additional `themes` variant uses `helium314.keyboard.compactthemesdebug`, distinct provider authorities and the launcher/IME identity **KEYNOVA SMART / كينوفا سمارت** (the Themes variant retains its distinct package ID). It can install alongside an older Compact APK even when its signing key is unavailable. Its preference storage is separate: use the existing Backup/Restore settings to transfer preferences and imported layouts on the phone. Neither installation is removed, overwritten or automatically migrated. Both APKs are built from the same patched source and exercised by the emulator workflow.

## Verification

`ThemeGalleryTest.kt` adds ten real engine regressions, covering the entire catalog, application/persistence, preview palette parity, typography isolation from the applied theme, correct Arabic/English alphabet selection, contrast, preference/file preservation, custom copies, bad data/image fallback, native control handover and defaults. Existing upstream failures remain visible in the existing full-suite comparison; no tests are excluded.

The debug-only `ThemeSmokeInstrumentation` runs inside the installed minified APK. It renders all 80 presets for both languages and both configurations, compares all renderer colors, checks unchanged key codes, exercises image handling/defaults and actual gallery card/preview/apply UI. Separate invocations verify persistence after force-stop, Arabic RTL resources, real keyboard taps in both orientations and native-versus-themed Ctrl+A/C/V, Alt, Tab and Shift interactions. Baseline limitations in the editor remain visible in its report. It writes reports/screenshots to the workflow verification artifact. The private input host and instrumentation are excluded from release variants. Device-specific shortcut handling and provider-specific voice transcription/session recovery still need a physical phone check; the existing ten voice controller regressions continue to run.

## Signing

No previous private signing key is present in the repository. The historical workflow generated temporary runner debug keys. This workflow caches the new Compact debug key so subsequent gallery builds can retain that identity. It cannot reconstruct an older installation's key. Therefore an older Compact APK may reject an in-place update with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`; retain the installed keyboard/settings and supply the original keystore for a compatible build. Do not uninstall the current keyboard as a workaround. A secured, persistent release keystore is still required for a production release channel.
